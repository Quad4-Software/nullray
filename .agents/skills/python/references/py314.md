# Python 3.14 detail

Source of truth: https://docs.python.org/3/whatsnew/3.14.html

Confirm feature availability against that page and the installed interpreter
before treating a bullet as production-ready.

## Free-threaded builds

- Officially supported under PEP 779
- Still a separate opt-in build (often a `python3.14t` binary)
- Expect single-thread overhead on the free-threaded build
- Audit C extensions for thread safety before enabling in production

## t-strings (PEP 750)

`t"..."` yields `string.templatelib.Template`, not `str`. Process static
segments and interpolations separately in sink-specific helpers (HTML, SQL
builders, shell). Keep f-strings for plain formatting.

## Deferred annotations

Annotations are deferred by default in 3.14. Use `annotationlib` when you need
to evaluate or inspect them. Tools that assumed eager evaluation at import time
need updates.

## Multiple interpreters

`concurrent.interpreters` exposes subinterpreters in the stdlib. Prefer message
passing over shared mutable state across interpreters.

## Other headlines (verify on whatsnew)

- Experimental JIT on some platform binaries
- Zstandard support in the stdlib
- Safer external debugger interface
- Incremental GC and interpreter improvements described in the release notes

## Upgrade steps

1. Read https://docs.python.org/3/whatsnew/3.14.html for removed and deprecated APIs
2. Run the test suite on 3.14 GIL builds first
3. Decide whether free-threaded is required. If yes, add a separate CI job
4. Replace unsafe string sinks with t-string helpers where applicable
5. Cap pickle, tarfile, and network parsers per [attack-surface](../../attack-surface/SKILL.md)
